# AI 예상문제 점검표

AI가 만든 예상문제를 붙여 넣으면 문제 유형, 예상 난이도, 학교 기출과의 차이를 보여 주는 웹 도구입니다. MOCKGAP 연구(AI 예상문제로 공부할 때 생기는 과신)에서 학생에게 보여 주는 "기출 비교 성적표"와 "다시 요청하기"를 따로 떼어 낸 것입니다.

- 점검표: https://phaduche.github.io/ai-mock-check/
- 기출로 기준 만들기: https://phaduche.github.io/ai-mock-check/baseline.html
- 실험 진행 페이지: https://github.com/Phaduche/mockgap-study

붙여 넣은 문항은 브라우저 안에서만 처리하고 어디로도 보내지 않습니다. 서버가 없습니다.

## 화면 순서

1. **문제 붙여 넣기:** AI 앱에서 받은 답을 정답·해설까지 통째로 붙여 넣습니다.
2. **기출과 비교:** 문제 유형, 예상 난이도, <보기> 합답형, 자료 해석·계산의 비율을 기출과 막대 두 줄로 나란히 보여 줍니다. 기출과 닮은 정도(%)와 가장 크게 부족한 점 세 가지를 문장으로 띄웁니다.
3. **문항별 결과:** 문항마다 유형, 예상 난이도, 그렇게 판단한 근거, 정답 유무를 보여 줍니다. 기준에 학교 문항분석표 정답률이 있으면 같은 유형의 기출 평균 정답률도 보여 줍니다.
4. **다시 요청하기:** 기출 비율에 맞춘 요청 문장을 만들어 줍니다. 새로 받은 답으로 다시 점검하면 닮은 정도가 어떻게 바뀌었는지 기록이 쌓입니다.
5. **풀어 보기:** 세트를 직접 풀고 유형별 정답률을 봅니다. 닮은 정도가 낮으면 "이 점수로 시험 점수를 짐작하면 안 된다"고 알려 줍니다.

## 돌려 볼 문제

점검표 1번 아래의 "돌려 볼 문제가 없으면" 칸에서 골라 **넣기**를 누르면 됩니다.

| 세트 | 어떻게 얻었나 | 기본 기준과 닮은 정도 |
| --- | --- | --- |
| AI에게 처음 받은 세트 (20문항) | Claude(Anthropic)에게 새 대화에서 연구의 요청 문장만 보냄: "통합과학2 교과서 화학 변화 단원(34~53쪽) 범위로 시험 예상문제를 20문항 만들어 줘. 객관식 16문항(보기 5개)과 서술형 4문항으로 하고, 각 문항마다 정답과 해설을 함께 적어 줘." | 32% (합답형 3문항, 자료·계산 4문항) |
| 다시 요청해서 받은 세트 (20문항) | 같은 대화에 점검표 4번 "다시 요청하기" 문장을 이어서 보냄 | 90% (합답형 14문항, 자료·계산 20문항) |
| 짧은 예시 (6문항) | 형식만 보여 주려고 쓴 예시 | 15% |

- 앞의 두 세트는 받은 답을 한 글자도 고치지 않고 `samples.js`에 넣었습니다(2026-11-12). 답을 쓴 AI는 이 저장소의 분류 규칙을 모르는 상태였습니다.
- 두 세트의 객관식 정답 32개와 서술형 모범 답안 8개는 Claude Code가 하나씩 풀어 확인했고 틀린 것은 찾지 못했습니다. 사람이 다시 확인한 것은 아닙니다.
- AI 하나에게 한 번씩 받은 답입니다. 연구의 예비 조사 자료가 아니고, AI 문제가 보통 이렇다는 증거도 아닙니다.
- **해 볼 순서:** 처음 세트를 넣고 점검하기 → 다시 요청해서 받은 세트를 넣고 점검하기. 4번 아래 표에 닮은 정도가 32%에서 90%로 바뀐 기록이 남습니다. 5번 "풀어 보기"에서 직접 풀어 볼 수도 있습니다.

### 다른 문제를 넣어 보려면

1. **내 AI로 받기:** 쓰는 AI 앱에 위 요청 문장을 보내고, 받은 답을 정답·해설까지 통째로 붙여 넣습니다.
2. **실제 기출로 기준 만들기:** 학교 기출이나 전국연합학력평가 문제([EBSi 기출문제](https://www.ebsi.co.kr/ebs/xip/xipc/previousPaperList.ebs))의 글자를 복사해 `baseline.html`에 붙여 넣습니다. 그림이나 표가 이미지로 된 문항은 글자가 빠지니 "표는 …", "그림은 …" 같은 발문이 남아 있는지 확인합니다.
3. **주의:** 기출 문항과 교과서 본문은 저작권이 있으니 이 저장소에 올리지 않습니다. 화면에 붙여 넣는 것은 내 브라우저 안에서만 처리되므로 괜찮습니다.

## 분류 규칙 (`classify.js`)

학습하지 않는 규칙입니다. AI 문제와 기출에 **같은 규칙**을 써야 비교가 공정하므로, 기준을 만들 때도 분류를 손으로 바꾸지 않습니다.

| 특징 | 알아보는 표시 |
| --- | --- |
| <보기> 합답형 | 발문에 &lt;보기&gt;와 "ㄱ." 진술이 있음, 또는 선지가 모두 "ㄱ, ㄴ" 조합 |
| 자료 해석 | 표, 그래프, 그림, 자료, 실험 결과, (가)·(나), [과정]·[결과], 챗 앱이 그린 표(`| … |`) |
| 계산 | "구하시오", "몇 mL" 같은 말이 있거나, 단위가 붙은 숫자(g, mL, ℃, % …)가 둘 이상 ("25 ℃에서" 하나만 있으면 계산이 아님) |
| 탐구 설계 | 설계, 실험 방법, 탐구 과정, 변인 |

| 유형 | 조건 | 예상 난이도 |
| --- | --- | --- |
| 서술형 | 서술형 문항 | 자료·계산·설계가 있으면 상, 아니면 중 |
| 응용 | 탐구 설계, 또는 자료+계산, 또는 합답형+(자료 또는 계산) | 상 |
| 개념 활용 | 자료 해석 또는 계산 하나 | 합답형이면 상, 아니면 중 |
| 개념 체크 | 위 표시가 없음 | 합답형이면 중, 아니면 하 |

- **닮은 정도:** 비교 항목마다 두 비율 분포의 총변동거리(0~1)를 구하고, (1 − 평균 거리) × 100으로 나타냅니다.
- **부족한 점 문장:** 기출보다 10%p 넘게 적은 칸만, 큰 순서로 최대 세 개를 보여 줍니다.
- **다시 요청 문장:** 객관식 16 + 서술형 4 기준으로 기출 비율을 문항 수로 바꿔 넣습니다.
- 문항 나누기(`parseAI`)는 mockgap-study / session-frame의 규칙에서 출발했고, 실제 AI 답을 돌려 보고 다음을 고쳤습니다(classify-v2).
  - `**해설** …`처럼 쌍점 없이 굵은 글씨로만 쓴 해설도 해설로 읽습니다. 전에는 마지막 선지에 붙었습니다.
  - 서술형의 소문항 (1), (2)를 선지로 세지 않습니다. 전에는 선지 2개짜리 객관식으로 읽고 "정답 없음"으로 표시했습니다.
  - 해설 속의 "(1)은 …, (2)는 …, (3)은 …"을 새 문항으로 읽지 않습니다. 전에는 20문항이 25문항으로 읽혔습니다.
  - 챗 앱의 구분선(`---`)과 맺음말은 문항에 붙이지 않습니다.
  - mockgap-study의 참가자 페이지는 아직 예전 규칙이라 같은 문제가 있습니다.

## 기출 기준

- **기본 기준:** `baselines.js`에는 지금 팀 연구 문서의 예비 조사 요약값 두 개(합답형 약 80%, 자료 해석·계산 약 90%, 기출 67문항)만 있습니다. 그래서 웹에서는 이 두 항목만 비교합니다.
- **기준 만들기:** `baseline.html`에 학교 기출을 붙여 넣으면 같은 규칙으로 유형·난이도 비율까지 계산합니다. 문항분석표가 있으면 문항별 정답률을 넣어 유형별 평균 정답률도 담습니다.
- **기준 파일에 담기는 것:** 비율과 평균 정답률뿐이고 문항 원문은 담기지 않습니다. 점검표의 "기준 파일" 칸에서 열면 그 브라우저에서만 쓰고, 모두가 쓰게 하려면 아래 "고치는 방법"대로 `baselines.js`에 추가합니다.
- **규칙 버전:** 기준 파일에는 만든 규칙 버전(`made_with`)이 적힙니다. 다른 버전으로 만든 기준을 열면 점검표가 알려 줍니다.

## 한계

- 유형과 난이도는 문장 속 표시로 정한 추정값입니다. 실제로 몇 명이 맞혔는지가 아닙니다.
- 그림만 있고 글자가 없는 문항, 이미지로 된 기출은 글자로 옮겨야 분류할 수 있습니다.
- 정답이 맞는지는 검사하지 않습니다. 정답이 빠진 문항만 표시합니다.
- 통합과학 문항으로 만든 규칙이라 다른 과목에서는 맞지 않을 수 있습니다.
- 규칙은 아래 "돌려 볼 문제"의 두 세트를 보면서 고쳤습니다. 그래서 이 두 세트는 규칙이 맞는지 보여 주는 증거가 아닙니다. 규칙의 정확도는 다른 세트를 사람이 직접 분류한 결과와 비교해야 알 수 있습니다.
- 닮은 정도는 기준에 들어 있는 비율만 비교합니다. 문제의 질이나 정답이 맞는지는 보지 않습니다.

## 고치는 방법

main에 올라간 내용은 1~2분 뒤 웹에 그대로 반영됩니다. 반영 상황은 저장소의 **Actions** 탭에서 볼 수 있습니다.

1. **작은 수정 (문구, 예시, 기준 추가):** GitHub에서 파일을 열고 연필 아이콘을 눌러 고친 뒤 **Commit changes**를 누릅니다.
2. **규칙이나 화면을 바꿀 때:** 커밋 화면에서 "Create a new branch"를 골라 **Pull request**를 엽니다. 자동 검사(`node tests/classify.test.js`)가 초록 체크면 **Merge** 합니다. 빨간 X면 무엇이 깨졌는지 눌러서 확인합니다.
3. **분류 규칙을 바꿀 때:** `classify.js` 맨 위의 `VERSION`을 올리고(예: `classify-v2`), 바뀐 결과에 맞게 `tests/classify.test.js`를 고칩니다. 예전 규칙으로 만든 기준을 열면 점검표가 경고합니다. 공정한 비교를 위해 기출 기준도 새 규칙으로 다시 만듭니다.
4. **기출 기준 추가:** `baseline.html`에서 만든 JSON을 `baselines.js`의 `[ ]` 안에 `,`로 이어 붙입니다. 맨 앞에 둔 기준이 기본으로 선택됩니다.
5. **내 컴퓨터에서 보기:** 저장소를 받아 `index.html`을 더블클릭하면 됩니다. 테스트는 `node tests/classify.test.js`입니다.

## AI 사용

이 저장소의 코드와 문서는 Claude Code(Anthropic)가 작성을 도왔습니다. 연구 계획서와 보고서는 학생이 직접 씁니다. 사람 대상 자료 수집은 IRB 승인 뒤에만 합니다.
